# Подготовка семейства шрифта к Google Fonts

Этот документ — контрольный список подготовки, а не гарантия принятия семейства Google Fonts. Отправка возможна только после отдельной проверки дизайна, авторских прав, лицензии, качества шрифтовых файлов и требований текущего процесса Google Fonts.

## 1. Что должно быть подтверждено до упаковки

- [ ] Название семейства уникально, допустимо и согласовано с правилами Google Fonts.
- [ ] Указаны все авторы, дизайнеры и участники, которых необходимо кредитовать.
- [ ] Подтверждено происхождение каждого глифа: оригинальный рисунок, собственная разработка либо законное основание для использования.
- [ ] Проверены права на сторонние SVG, контуры, изображения, шрифтовые исходники и производные материалы.
- [ ] Все правообладатели согласны с лицензированием всего семейства под SIL Open Font License 1.1.
- [ ] Проверены требования Google Contributor License Agreement для правообладателей и участников.
- [ ] Авторские строки, URL, версия и лицензия одинаково и корректно отражены в бинарных файлах и метаданных пакета.

**Важно:** MIT-лицензия репозитория GlyphFlow не лицензирует автоматически шрифты, создаваемые пользователями. Не создавать OFL.txt, не указывать `license: "OFL"` и не помещать семейство в каталог `ofl/`, пока правообладатель явно не выбрал OFL 1.1 и не подтвердил право так лицензировать весь набор материалов.

## 2. Предварительная структура семейства

Пример структуры для одного статического начертания; конкретный состав уточняется по текущему Google Fonts Guide и способу onboarding:

```text
<family-directory>/
├── <FamilyName>-Regular.ttf
├── METADATA.pb
├── OFL.txt
├── DESCRIPTION.en_us.html
├── article/
│   └── ARTICLE.en_us.html
└── upstream.yaml
```

- TTF — финальный проверенный файл шрифта.
- METADATA.pb — семейство, дизайнеры, категория, лицензия, стили, веса, имена и сведения об исходном репозитории.
- OFL.txt — только точный официальный текст лицензии, выбранной правообладателями, с корректным copyright notice.
- DESCRIPTION.en_us.html — краткое описание семейства для каталога.
- article/ARTICLE.en_us.html — расширенная статья о дизайне и проекте, если требуется процессом.
- upstream.yaml — связь опубликованного семейства с исходным репозиторием и файлами, если используется соответствующий packager workflow.

Не генерировать фиктивные данные, дату добавления, имена, URL, веса, категории, подмножества или сведения о репозитории. Значения должны быть подтверждены исходными файлами и автором.

## 3. Согласование OpenType name table

Перед упаковкой проверить как минимум:

- Name ID 0 — Copyright notice.
- Name ID 1 и/или 16 — Family / Typographic Family.
- Name ID 2 и/или 17 — Subfamily / Typographic Subfamily.
- Name ID 3 — Unique font identifier.
- Name ID 4 — Full font name.
- Name ID 5 — Version.
- Name ID 6 — PostScript name.
- Name ID 7 — Trademark, если применимо.
- Name ID 8 — Manufacturer, если применимо.
- Name ID 9 — Designer.
- Name ID 10 — Description.
- Name ID 11–14 — URL издателя/дизайнера и лицензия, если эти сведения действительно заданы.

Имена в METADATA.pb должны совпадать с соответствующими записями в name table и именами файлов. Нельзя считать техническое имя глифа (например, `uniXXXX`) официальным Unicode Character Name.

## 4. Техническая проверка

- [ ] Файл имеет корректную сигнатуру TrueType и таблицы `cmap`, `head`, `hhea`, `maxp`, `OS/2`, `name`, `post`, `glyf`, `loca`.
- [ ] Все заявленные кодовые точки реально присутствуют в cmap.
- [ ] Нет случайных дубликатов кодовых точек, пустых обязательных глифов или повреждённых контуров.
- [ ] Проверены направление контуров, отверстия, вложенные области, самопересечения и экстремальные точки.
- [ ] Проверены ширины, боковые интервалы, вертикальные метрики, пробелы, пунктуация и базовые пары кернинга, если они заявлены.
- [ ] Проверено отображение на реальных строках и языках, которые заявлены в METADATA.pb.
- [ ] TTF открыт и проверен независимыми инструментами, включая FontTools; файл протестирован в нескольких приложениях и системах.
- [ ] Выполнен актуальный Google Fonts profile в Fontspector; каждый FAIL рассмотрен, а WARN объяснён. Для воспроизводимости зафиксировать версию Fontspector и сохранить HTML/JSON-отчёты.

### Независимая автоматическая проверка Fontspector

В CI GlyphFlow закреплён Fontspector CLI `1.9.1` и запускается профиль `opentype` на реальном TrueType fixture, созданном предыдущим smoke-тестом. Порог `--error-code-on fail` делает любой результат FAIL ошибкой CI; WARN сохраняются в отчёте и требуют отдельного рассмотрения. HTML- и JSON-отчёты сохраняются как CI artifact на 14 дней.

Пример локального запуска на готовом файле:

```bash
fontspector --profile opentype --html fontspector-opentype.html --json fontspector-opentype.json MyFont.ttf
```

Профиль `googlefonts` запускать только на полном кандидате семейства после подготовки реальных `METADATA.pb`, OFL 1.1 и остальных материалов пакета:

```bash
fontspector --profile googlefonts --html fontspector-googlefonts.html --json fontspector-googlefonts.json path/to/family-directory/*.ttf
```

Не запускать Google Fonts profile на CI-fixture GlyphFlow: у него тестовые метаданные и фиктивный текст лицензии. Успешный `opentype` profile не означает готовность к Google Fonts и не заменяет проверку прав, лицензии, shaping и визуальную экспертизу.
- [ ] Проведена визуальная проверка пробных листов: согласованность дизайна, качество контуров, интервалы, отсутствие пропусков и ошибок shaping.

## 5. Сведения о составе глифов

Для каждого глифа хранить отдельно:

- сам символ и его Unicode code point;
- официальное Unicode Character Name (только если оно подтверждено Unicode Character Database);
- OpenType glyph name — отдельное техническое имя;
- описание формы и назначения;
- категорию и Script;
- источник рисунка / авторство и статус проверки;
- наличие глифа в cmap экспортированного файла.

## 6. Финальный gate

Пакет получает статус «готов к отправке» только после выполнения всех применимых пунктов выше, проверки всех файлов пакета и ручного одобрения правообладателя. Автоматический отчёт GlyphFlow — вспомогательная проверка, а не решение Google Fonts о приёме семейства.
