# Стандарт имён и описаний глифов GlyphFlow

Цель — давать каждому символу однозначную Unicode-идентификацию, техническое имя глифа OpenType и краткое описание, не смешивая эти разные сущности.

## 1. Три отдельных поля

1. **Unicode Character Name** — официальное имя кодовой точки из закреплённой версии Unicode Character Database (UCD). Оно не придумывается редактором и не переименовывается по вкусу автора.
2. **OpenType glyph name** — техническое имя глифа внутри шрифта. Для него применяются AGLFN там, где есть подходящее рекомендуемое имя; в остальных случаях — конвенции `uniXXXX` для BMP и `uXXXXX` для дополнительных плоскостей.
3. **Описание** — краткое пояснение на естественном языке. Это не официальное свойство Unicode и не замена имени символа.

Unicode-имя является стабильным идентификатором символа, но не всегда совпадает с привычным названием, назначением или термином конкретного сообщества. Поэтому описание хранится отдельно.

## 2. Правила технического имени

- Для кодовой точки BMP без подходящего имени AGLFN использовать `uni` + четыре заглавные шестнадцатеричные цифры, например `uni0401`.
- Для дополнительной плоскости использовать `u` + заглавное шестнадцатеричное значение с минимум пятью цифрами, например `u1F600`.
- Если AGLFN содержит рекомендуемое имя для символа, использовать его вместо механического имени.
- Суффиксы после точки применять только для различения вариантов одного базового глифа, например `.alt01`, `.sc`, `.swsh`; они не должны менять Unicode-семантику базового имени.
- Для последовательностей из нескольких кодовых точек нельзя назначать один обычный cmap mapping без явно предусмотренного механизма последовательности/лигатуры.
- Не выдавать `uniXXXX` или `uXXXXX` за официальное Unicode Character Name.

AGL/AGLFN — инструменты сопоставления имён глифов и Unicode, а не источник официальных Unicode Character Names. Для новых шрифтов следует ориентироваться на AGLFN и спецификацию Adobe Glyph List.

## 3. Правила описания

Описание глифа должно быть:

- кратким, нейтральным и проверяемым;
- основанным на официальном Unicode-описании или на реально видимой форме символа;
- без выдуманного происхождения, культурной трактовки, произношения или значения;
- отделённым от авторского комментария и художественной интерпретации;
- помеченным как локальное/редакторское, если оно не является официальным текстом Unicode.

Для букв указывать название и при необходимости отличительную графическую особенность. Для цифр — тип цифры и значение. Для пунктуации и математических знаков — официальное название и общеупотребительное назначение, если оно однозначно. Для неизвестных или частных символов — нейтральное описание формы с пометкой, что официального Unicode-имени нет.

## 4. Паспорт глифа в GlyphFlow

JSON-паспорт должен сохранять раздельно:

- `character` — сам символ;
- `codePoint` и `codePointValue` — кодовая точка;
- `unicodeName` — официальное имя UCD либо `null`, если его нет;
- `glyphName` — техническое имя OpenType;
- `description` — краткое описание;
- `generalCategory` — Unicode General Category;
- `script` — Unicode Script;
- `metadataSource` / сведения об источнике и версии — происхождение метаданных;
- `validationStatus` — статус проверки глифа.

В паспорте семейства отдельно сохраняются дизайнер, издатель, версия, описание, copyright, trademark, лицензия и URL. Данные об авторстве и лицензии не выводятся из Unicode и не назначаются автоматически.

## 5. Проверка перед выпуском

- [ ] Каждый символ — одна корректная Unicode scalar value либо явно обозначенная последовательность.
- [ ] Unicode Character Name сверено с закреплённым UCD.
- [ ] Glyph name соответствует AGLFN или документированной технической конвенции.
- [ ] Описание не подменяет официальное имя и не содержит неподтверждённых толкований.
- [ ] Кодовая точка присутствует в cmap итогового файла.
- [ ] Паспорт JSON согласован с фактическим составом TTF.
- [ ] Если экспортируемый формат/таблица не сохраняет имена глифов, паспорт JSON остаётся сопровождающим источником расширенных имён и описаний.
