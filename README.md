# GlyphFlow

**GlyphFlow** — браузерный редактор рукописных шрифтов. Рисуйте символы каллиграфической кистью, проверяйте результат в текстовом предпросмотре и собирайте собственный файл шрифта TrueType (.ttf).

> Текущий статус: ранний MVP. Приложение уже умеет рисовать отдельные глифы и собирать TTF, но ещё не является полноценным профессиональным редактором шрифтов.

## Что работает сейчас

- Каллиграфическая кисть на базе [perfect-freehand](https://github.com/steveruizok/perfect-freehand).
- Настройка размера кисти и заострения концов.
- Рабочее поле SVG с типографскими направляющими.
- Набор символов: кириллица, латиница, цифры и часть пунктуации.
- Переключение между глифами.
- Выбор отдельного штриха в режиме редактирования контуров.
- Назначение контуру роли «внешний» или «отверстие»; старые черновики без роли автоматически считаются внешними.
- Составной SVG-контур с противоположным направлением обхода для отверстий.
- Отмена и повтор действий в рамках текущей сессии.
- Локальное сохранение черновика в IndexedDB и попытка восстановления при повторном открытии.
- Текстовый предпросмотр и экспорт настоящего TTF через [opentype.js](https://github.com/opentypejs/opentype.js) и [fonteditor-core](https://github.com/kekee000/fonteditor-core).

## Запуск

Откройте `index.html` через локальный HTTP-сервер. Например, при установленном Python:

```bash
python -m http.server 8000
```

Затем перейдите на `http://localhost:8000`. Для загрузки модулей из CDN при первом запуске требуется подключение к интернету.

## Как пользоваться

1. Выберите символ в левой панели.
2. Нарисуйте его на белом поле.
3. Настройте толщину и заострение кисти.
4. Перейдите к другим символам и нарисуйте нужный набор.
5. Введите текст в поле предпросмотра.
6. Задайте название семейства и нажмите «Скачать .TTF».

Черновик хранится локально в браузере на этом устройстве. Очистка данных сайта или хранилища браузера может удалить черновик. Это не облачная синхронизация и не резервная копия.

## Известные ограничения

- Пока доступна только каллиграфическая кисть; карандаш, перо Безье и векторный ластик ещё не реализованы.
- История действий пока простая и ограничена текущей сессией.
- Нет импорта SVG, слоёв, полноценного редактирования узлов и кернинга.
- Проверка положения отверстия пока основана на ограничивающей рамке внешнего контура и отсутствии пересечения границ; полноценная топологическая проверка и Boolean-операции ещё требуются.
- Сложные самопересечения и объединение пересекающихся штрихов требуют дальнейшей геометрической доработки.
- Метрики шрифта и боковые интервалы требуют отдельной типографской доработки.
- PWA, Service Worker и гарантированная офлайн-работа пока не реализованы.
- Внешние библиотеки загружаются с CDN.

## План развития

1. Укрепить ввод указателя, восстановление и тестирование на мобильных устройствах.
2. Развить модель глифов и надёжную историю изменений.
3. Развить геометрический валидатор: точная проверка вложенности, Boolean-объединение и самопересечения контуров.
4. Реализовать карандаш и перо Безье.
5. Добавить выделение, векторный ластик, слои и импорт SVG.
6. Улучшить метрики, направляющие, предпросмотр и кернинг.
7. Добавить PWA, офлайн-режим и автоматические тесты.

## Технологии

- HTML, CSS и JavaScript (ES modules)
- SVG для векторного рабочего поля
- perfect-freehand для построения каллиграфических контуров
- opentype.js для промежуточного построения OTF и fonteditor-core для конвертации в TrueType TTF
- IndexedDB для локальных черновиков

## Автоматические проверки

GitHub Actions проверяет синтаксис встроенного JavaScript и ключевые контракты редактора, затем создаёт промежуточный OTF через opentype.js 1.3.4, конвертирует его в настоящий TTF через fonteditor-core и проверяет итоговый файл через opentype.js и независимый Python FontTools. Проверяются сигнатура TrueType, таблицы `glyf`/`loca`, метрики, `.notdef`, пробел, Unicode, количество контуров, а также противоположное направление внешнего контура и отверстия.

Эти проверки полезны для контроля сборки, но не заменяют ручную проверку рисунка букв, браузеров и сторонних шрифтовых редакторов.



### Автоматическая проверка в браузере

GitHub Actions запускает Chromium + Playwright и проверяет рисование, Undo/Redo, восстановление IndexedDB после перезагрузки, работу с отдельными глифами и скачивание настоящего TTF. Успешный прогон подтверждён на Linux Chromium; проверка реальных Android/iOS устройств и других браузеров остаётся отдельным этапом.


### Сенсорный ввод и отмена штриха

Playwright в Chromium дополнительно проверяет сенсорный жест: нормальное касание сохраняет штрих, а прерванное касание (`touchcancel`) и `pointercancel` отменяют незавершённый рисунок. Также проверяется, что переключение символа не переносит частичный штрих в другой глиф.

Эти тесты используют эмуляцию сенсорных событий в Chromium и не заменяют физическую проверку на Android/iOS. Реальные устройства, стилусы и другие браузеры остаются следующим этапом.


### Внешние контуры и отверстия

Включите режим «Выбрать контур», нажмите на нужный штрих и назначьте ему тип. Старые сохранённые штрихи и новые рисунки по умолчанию имеют роль внешнего контура. Отверстие можно назначить только контуру, который находится внутри ограничивающей рамки другого внешнего контура и не пересекает его границу. При отрисовке и экспорте составной глиф использует противоположное направление обхода для внешних областей и отверстий.

Это первая рабочая версия модели контуров, а не полноценное CAD-ядро: ограничивающая рамка не доказывает геометрическую вложенность во всех сложных формах. Для сложных букв, самопересечений и пересекающихся мазков предстоит добавить точные Boolean-операции и визуальные тесты.

### Масштабирование и перемещение холста

Холст можно увеличивать и уменьшать кнопками или колёсиком мыши, возвращать к исходному масштабу и сдвигать стрелками. Для мыши также доступно перетаскивание с Alt или средней кнопкой. Масштабирование сохраняет исходные координаты штрихов и синхронно двигает типографские направляющие. Рабочая область подстраивается под узкий экран.

Двухпальцевое масштабирование и перемещение проверяются автоматическим тестом с эмуляцией двух касаний в Chromium. Ручная проверка на физических Android/iOS устройствах ещё не проводилась. Поддержка давления пера пока предварительная: значение pressure передаётся в точки Pointer Events, но работа стилуса на физическом устройстве ещё не подтверждена. Реальные устройства Android/iOS ещё не проходили ручную проверку.
