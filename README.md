# GlyphFlow

**GlyphFlow** — браузерный редактор рукописных шрифтов. Рисуйте символы каллиграфической кистью, проверяйте результат в текстовом предпросмотре и собирайте собственный файл шрифта TrueType (.ttf).

> Текущий статус: расширенный MVP на этапе стабилизации. Редактор, векторная геометрия, экспорт TTF, автоматические проверки и локальная PWA-сборка реализованы; перед выпуском остаются реальные мобильные испытания и дальнейшее развитие типографских инструментов.

## Что работает сейчас

- Каллиграфическая кисть на базе [perfect-freehand](https://github.com/steveruizok/perfect-freehand).
- Настройка размера кисти и заострения концов.
- Рабочее поле SVG с типографскими направляющими.
- Набор символов: кириллица, латиница, цифры и часть пунктуации.
- Переключение между глифами.
- Карточка каждого текущего символа: Unicode code point/name, glyph name, Unicode General Category, Script и описание.
- Runtime-каталог свойств Unicode 18.0.0: редактор загружает официальные имена, General Category и Combining Class из UnicodeData.txt, Script из Scripts.txt; поддерживаемые алгоритмические диапазоны (CJK, Hangul, Tangut, Nushu и Khitan) раскрываются по правилам Unicode. Это полный набор именно перечисленных свойств, а не все файлы UCD.
- Метаданные Unicode и имена глифов OpenType разделены: официальное имя берётся из UCD, а имя глифа использует AGLFN там, где применимо, иначе `uniXXXX`/`uXXXXX` как техническую конвенцию, а не как официальное имя Unicode.
- Runtime-каталог создаётся из закреплённых официальных файлов UCD при production-сборке, загружается в фоне и кешируется Service Worker. Если каталог недоступен, редактор остаётся рабочим с явно помеченным локальным набором метаданных.
- Отдельный экспорт JSON-паспорта нарисованных глифов с Unicode mapping, именами, описаниями и статусом проверки; файл сопровождает TTF и не встраивается в его бинарную структуру. Источник UCD закреплён на версии Unicode 18.0.0.
- Выбор отдельного штриха в режиме редактирования контуров.
- Назначение глубины контура: внешний (0), отверстие (1), остров внутри отверстия (2), отверстие внутри острова (3); старые черновики автоматически мигрируют.
- Boolean-объединение пересекающихся кистевых штрихов в единую форму на каждом уровне вложенности.
- Чередование объединения и вычитания для четырёх уровней вложенности; геометрия SVG и TTF строится из одного составного результата.
- Поддержка нескольких независимых отверстий в одном глифе; автотест проверяет прозрачность обоих отверстий в итоговом TTF.
- Составной SVG-контур с правильным направлением обхода внешних областей и отверстий.
- Отмена и повтор действий; история ограничена 40 снимками и ориентиром 8 МиБ, чтобы сдерживать расход памяти.
- Локальное сохранение черновика в IndexedDB и попытка восстановления при повторном открытии.
- Текстовый предпросмотр и экспорт настоящего TTF через [opentype.js](https://github.com/opentypejs/opentype.js) и [fonteditor-core](https://github.com/kekee000/fonteditor-core).
- Редактируемые метаданные семейства: дизайнер, издатель, версия, описание, уведомление об авторском праве, товарный знак, текст лицензии и ссылки. Данные сохраняются в проекте и JSON-паспорте глифов, а поддерживаемые поля записываются в OpenType `name` table при экспорте. Пустые лицензионные поля не назначают лицензию.
- Полностью локальная сборка runtime-зависимостей: perfect-freehand, fonteditor-core, opentype.js, polygon-clipping и Tailwind CSS входят в Vite bundle; runtime CDN-запросы не нужны.
- Устанавливаемая PWA: Web App Manifest, фирменная SVG-иконка, Service Worker и кеширование локальных JS/CSS-ресурсов после первого посещения.

## Запуск

Установите Node.js 22 или новее и выполните:

```bash
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно `http://localhost:5173`). Для production-сборки выполните `npm run build`; prebuild автоматически проверит и подготовит закреплённый Unicode 18.0.0 runtime-каталог, затем результат появится в `dist/`. Просмотр готовой сборки: `npm run preview`.

## Публикация сайта

Для GitHub Pages подготовлен workflow `.github/workflows/deploy-pages.yml`. Он собирает статическую PWA-версию и публикует её после обновления `main` (или ручного запуска workflow). Изменения текущей рабочей ветки пока не опубликованы: draft PR не сливается автоматически. После одобрения и слияния PR GitHub Actions выполнит публикацию; фактический URL появится в результате deployment job.

## Как пользоваться

1. Выберите символ в левой панели.
2. Нарисуйте его на белом поле.
3. Настройте толщину и заострение кисти.
4. Перейдите к другим символам и нарисуйте нужный набор.
5. Введите текст в поле предпросмотра.
6. Задайте название семейства, при необходимости заполните раскрываемый раздел «Метаданные шрифта» и нажмите «Скачать .TTF». Пустые сведения об авторстве или лицензии не заполняются автоматически.

Черновик хранится локально в браузере на этом устройстве. Очистка данных сайта или хранилища браузера может удалить черновик. Это не облачная синхронизация и не резервная копия.

## Известные ограничения

- Пока доступна только каллиграфическая кисть; карандаш, перо Безье и векторный ластик ещё не реализованы.
- История Undo/Redo ограничена текущей сессией и бюджетом памяти; после восстановления черновика состояние проекта восстанавливается, но прежняя история отмены не сохраняется.
- Есть редактирование центральной траектории штриха и его исходной векторной границы. Пока нет редактирования объединённого итогового MultiPolygon после Boolean union, импорта SVG, слоёв и кернинга.
- Проверка положения отверстия выполняется относительно объединённой внешней формы: отверстие должно полностью находиться внутри неё и не касаться её границы. Геометрические операции union/difference выполняются библиотекой polygon-clipping. Сложные самопересечения и неоднозначные рукописные формы всё ещё требуют дополнительных тестов.
- Автотесты проверяют самопересекающуюся траекторию «∞»: геометрия разбивается на два корректных контура, включая внутреннюю область. Другие сложные самопересечения, тонкие перемычки и редкие вырожденные формы требуют дальнейшей проверки.
- Метрики шрифта и боковые интервалы требуют отдельной типографской доработки.
- Автономная работа проверяется в Chromium после первого успешного посещения и кеширования локальных ресурсов. Поведение установки и offline-режима всё ещё нужно подтвердить на физических Android/iOS устройствах и в разных браузерах.

## План развития

## Автоматические проверки

GitHub Actions проверяет синтаксис локального ES-модуля и ключевые контракты редактора, собирает production PWA через Vite, затем создаёт промежуточный OTF через opentype.js 1.3.4, конвертирует его в настоящий TTF через fonteditor-core и проверяет итоговый файл через opentype.js и независимый Python FontTools. Проверяются сигнатура TrueType, таблицы `glyf`/`loca`, метрики, `.notdef`, пробел, Unicode, количество контуров, а также противоположное направление внешнего контура и отверстия.

Эти проверки полезны для контроля сборки, но не заменяют ручную проверку рисунка букв, браузеров и сторонних шрифтовых редакторов.



### Автоматическая проверка в браузере

GitHub Actions запускает Chromium + Playwright. Набор проверяет рисование, Undo/Redo, IndexedDB, сенсорные жесты, масштабирование, Boolean-геометрию, экспорт TTF, редактирование траекторий и контуров, длительные сессии, PWA/offline, сохранение метаданных проекта и чтение метаданных из экспортированного TTF. Число сценариев меняется вместе с тестовым набором; актуальный список находится в `tests/browser/editor.spec.mjs`. CI выполняется на Linux Chromium. Эмуляция устройств не заменяет ручную проверку на физических Android/iOS устройствах и стилусах.

### Сенсорный ввод и отмена штриха

Playwright в Chromium дополнительно проверяет сенсорный жест: нормальное касание сохраняет штрих, а прерванное касание (`touchcancel`) и `pointercancel` отменяют незавершённый рисунок. Также проверяется, что переключение символа не переносит частичный штрих в другой глиф.

Эти тесты используют эмуляцию сенсорных событий в Chromium и не заменяют физическую проверку на Android/iOS. Реальные устройства, стилусы и другие браузеры остаются следующим этапом.


### Внешние контуры и отверстия

Включите режим «Выбрать контур», нажмите на нужный штрих и назначьте ему тип. Старые сохранённые штрихи и новые рисунки по умолчанию имеют роль внешнего контура. Отверстие можно назначить только контуру, который полностью находится внутри объединённой фактической геометрии родительского уровня и не касается её границы. Проверка использует Boolean difference, а не только ограничивающую рамку. При отрисовке и экспорте составной глиф использует противоположное направление обхода для внешних областей и отверстий.

Это рабочая модель четырёх уровней вложенности, но ещё не полноценное CAD-ядро: сложные самопересечения, тонкие перемычки и неоднозначные касания требуют дополнительных тестов.

### Масштабирование и перемещение холста

Холст можно увеличивать и уменьшать кнопками или колёсиком мыши, возвращать к исходному масштабу и сдвигать стрелками. Для мыши также доступно перетаскивание с Alt или средней кнопкой. Масштабирование сохраняет исходные координаты штрихов и синхронно двигает типографские направляющие. Рабочая область подстраивается под узкий экран.

Двухпальцевое масштабирование и перемещение проверяются автоматическим тестом с эмуляцией двух касаний в Chromium. Ручная проверка на физических Android/iOS устройствах ещё не проводилась. Поддержка давления пера пока предварительная: значение pressure передаётся в точки Pointer Events, но работа стилуса на физическом устройстве ещё не подтверждена. Реальные устройства Android/iOS ещё не проходили ручную проверку.


### Вложенная геометрия контуров

Геометрическое ядро поддерживает явную глубину контура в данных штриха (`depth`):
- уровень 0 — внешняя заполненная область;
- уровень 1 — отверстие;
- уровень 2 — заполненный остров внутри отверстия;
- уровень 3 — отверстие внутри острова; далее уровни чередуются.

Штрихи одного уровня сначала объединяются, затем уровни применяются от внешнего к внутреннему через Boolean union/difference. Старые черновики без `depth` сохраняют прежнее поведение: `outer` соответствует уровню 0, `hole` — уровню 1. Новый механизм проверяется отдельным геометрическим fixture с четырьмя уровнями вложенности. В интерфейсе доступны четыре уровня вложенности; назначение проверяется относительно объединённой геометрии родительского уровня. Сложные касания и самопересечения всё ещё требуют дополнительных тестов.


В интерфейсе редактора можно назначить штриху один из четырёх уровней вложенности: внешняя область, отверстие, остров внутри отверстия и отверстие внутри острова. Для уровней 1–3 редактор проверяет, что новый контур находится внутри объединённой области родительского уровня и не касается её границы. Старые черновики с ролями outer/hole продолжают открываться как уровни 0/1.


### Сохранение вложенных контуров

Назначенные уровни 0–3 сохраняются вместе с данными штрихов в IndexedDB. Автоматические проверки охватывают чтение этих данных после перезагрузки, восстановление уровня после Undo/Redo и сохранение уровней при переключении между символами. Эти сценарии выполняются в Chromium через Playwright; результаты актуального CI см. в [GitHub Actions](https://github.com/Lina1209/GlyphFlow/actions).


При восстановлении черновика редактор также нормализует старые записи: прежняя роль `hole` переносится в глубину 1, а неподдерживаемые значения глубины приводятся к совместимому уровню по старой роли. Это предотвращает появление невидимых или невыбираемых уровней в четырёхуровневом интерфейсе.


### Плавность рисования

Промежуточное отображение штриха обновляется не на каждое событие указателя, а не чаще одного раза за кадр анимации. Сами точки траектории при этом продолжают накапливаться; при завершении или отмене штриха ожидающий кадр отменяется. Это уменьшает число полных перерисовок SVG при частом вводе. В Chromium есть регрессионный тест с 400 событиями указателя в одном потоке.


### Проверка производительности геометрии

CI запускает отдельный performance smoke test для плотной траектории из 512 точек, 32 пересекающихся кистевых штрихов и 32 контуров с четырьмя уровнями вложенности. Он измеряет время построения, количество итоговых контуров, примерное изменение heap и повторный вызов с кэшем. Это воспроизводимый контрольный замер, а не обещание одинаковой скорости на всех устройствах.


### Контроль памяти при длительном редактировании

История Undo хранит полные снимки проекта, поэтому она ограничена двумя независимыми пределами: максимум 40 снимков (текущий плюс до 39 шагов отмены) и ориентировочно 8 MiB строк JSON в UTF-16. При превышении любого предела удаляются самые старые снимки, а актуальное состояние и возможность Undo/Redo сохраняются. Это оценка размера строк истории, а не точный замер всей памяти JavaScript.


Повторные экспорты также проверяются на освобождение временных Blob URL. Отложенная очистка захватывает отдельную неизменяемую ссылку на URL, чтобы последующее обнуление переменной не мешало таймеру освободить ресурс.


### Большие глифы и длительная мобильная сессия

Performance smoke suite расширен измерениями для одной траектории на 2 000, 5 000 и 10 000 точек, а также для 64 и 128 отдельных кистевых штрихов. Для каждого сценария выводятся число входных точек, количество выходных контуров, время построения, cache-hit и приблизительное изменение heap. Общий допуск stress-suite увеличен до 90 секунд; это регрессионный предел CI, а не рекомендация по максимальному размеру глифа.

В Chromium добавлен сценарий многократного рисования на ширинах 320, 360 и 412 CSS px, переключения между двумя глифами, проверки независимости IndexedDB-данных и повторных Undo/Redo. Это эмуляция viewport в настольном Chromium, а не физический Android-тест.


## Ручная проверка на телефоне

См. [MOBILE_TEST_CHECKLIST.md](./MOBILE_TEST_CHECKLIST.md). Playwright уже проверяет узкие окна, touch/pointer cancellation, pinch/pan и повторные сессии, но это не заменяет проверку на настоящем сенсорном экране.


### Редактирование узлов траектории

Добавлен отдельный режим «Редактировать узлы». Выберите нарисованный штрих — редактор покажет его исходные точки траектории. Перетаскивайте круглые маркеры, чтобы локально менять форму штриха; результат сразу пересчитывается через perfect-freehand и обновляет составной контур. Для плотных траекторий отображается не более 49 равномерно распределённых маркеров, включая конечную точку, чтобы не перегружать холст. Завершённое перемещение записывается одним действием в Undo/Redo и сохраняется в IndexedDB. Отмена указателя возвращает точку в исходное положение. Это редактирование точек центральной линии кистевого штриха, а не полноценное редактирование узлов итогового Bézier/SVG-контура.


### Добавление и удаление точек траектории

В режиме «Редактировать узлы» выберите точку траектории, чтобы включить команды «Добавить точку» и «Удалить точку». Новая точка вставляется посередине соседнего сегмента; координаты и давление кисти интерполируются, если pressure присутствует в исходных точках. Удаление разрешено, пока в штрихе остаётся минимум две точки. Каждая операция является отдельным шагом Undo/Redo и сохраняется в локальный черновик.


### Редактирование векторной границы

Новый режим «Редактировать границу» позволяет выбрать штрих и перетаскивать вершины его фактического полигонального контура, сформированного кистью. Изменённая граница хранится как `outlineOverride` внутри данных штриха, поэтому сохраняется в IndexedDB и включается в Boolean-объединение, предпросмотр и TTF-экспорт. Для плотных контуров показывается до 49 равномерно выбранных маркеров, при этом каждый маркер указывает на исходную вершину. Отклоняются вырожденные изменения и смена направления обхода контура; существующие касания и особенности исходной кистевой геометрии не блокируют локальное редактирование. Корректность объединения дополнительно проверяется Boolean pipeline. Undo/Redo и отмена указателя поддерживают восстановление исходной геометрии. При перекрытии близко расположенных маркеров точка выбирается по минимальному расстоянию до места нажатия, а не только по верхнему SVG-элементу; это уменьшает ошибки выбора на плотных контурах и сенсорных экранах.

Редактирование границы и редактирование центральной траектории — разные операции. При последующем изменении центральной траектории ручная граница сбрасывается, чтобы не оставлять несогласованные данные.

## Локальная библиотека шрифтов

GlyphFlow включает локальную библиотеку, которая работает в браузере без аккаунта и внешнего сервера:

- сохраняет созданные TrueType TTF вместе с исходным редактируемым проектом;
- импортирует готовые TTF и OTF после проверки файла парсером шрифтов;
- позволяет искать, скачивать и удалять записи;
- открывает сохранённый проект обратно в редакторе;
- экспортирует и восстанавливает резервную копию библиотеки в JSON.

Файлы и проекты хранятся в IndexedDB текущего браузера на текущем устройстве. Они не синхронизируются автоматически между устройствами и могут быть удалены очисткой данных сайта. Для переноса или страховочной копии используйте кнопку «Резервная копия» в разделе библиотеки. Импортированный TTF/OTF хранится как файл; исходные глифы для редактирования доступны только у шрифтов, созданных и сохранённых непосредственно из редактора.


## Подготовка шрифта к публикации

Требования к архиву семейства, метаданным, проверкам TTF и лицензионному решению собраны в [FONT_PUBLICATION_CHECKLIST.md](./FONT_PUBLICATION_CHECKLIST.md). Лицензия конкретного создаваемого шрифта не назначается автоматически: выбор и подтверждение правообладателя необходимы до формирования лицензионного файла.
